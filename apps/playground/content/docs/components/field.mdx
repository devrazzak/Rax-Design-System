## Usage

```tsx
import { Field, FieldDescription, FieldError, FieldLabel, Input } from '@rax-ds/ui';

export function EmailField({ error }: { error?: string }) {
    return (
        <Field data-invalid={!!error}>
            <FieldLabel htmlFor="email">Email</FieldLabel>
            <Input id="email" type="email" aria-invalid={!!error} aria-describedby="email-hint email-error" />
            <FieldDescription id="email-hint">We never share your email.</FieldDescription>
            <FieldError id="email-error">{error}</FieldError>
        </Field>
    );
}
```

Field lays out the label, the control, the hint and the error. It does not connect them, so pass `id`, `aria-invalid` and `aria-describedby` to the control yourself. It works with [Input](/docs/components/input), [Textarea](/docs/components/textarea), [Select](/docs/components/select) and the other controls, and uses no form library.

## Accessibility

- `FieldError` renders `role="alert"`, so screen readers announce it when it appears, and renders nothing when it has no children.
- `FieldSet` renders a native `<fieldset>` and `FieldLegend` a `<legend>`, which screen readers announce before the controls inside.
- Link the label with `htmlFor` and `id`, and the hint and error with `aria-describedby`.
- `data-invalid` only changes the color. Set `aria-invalid` on the control as well.
